Frosthaven Mods

Mod guide · version __VERSION__ · what each mod does and how to use it
The short version: everyone installs the same version of the mods. The host turns on the mods the group wants in Options > Custom Rules. Everything else happens in the game as usual.

Installing and updating

  1. Close Frosthaven.
  2. Download Install Frosthaven Mods.exe from the latest release: github.com/Kalarian/Frosthaven-Mods/releases/latest
  3. Run it and click Install / Update. If Windows warns you, click More info, then Run anyway.
  4. The installer always fetches the newest version, so you can keep the same file and run it again for updates.

Everyone in a co-op game must have the same version. The game won't stop you from joining with a different one; instead, things go out of sync partway through a scenario. If you're not sure, everyone runs the installer before you play.

To remove the mods, run the installer and click Remove mods. Your saves are never changed, and a campaign played with the mods still loads without them.

Turning mods on and off

  • Every mod is a switch in Options > Custom Rules while a campaign is loaded. All of them start off.
  • The host decides. The switches are saved with the campaign and sent to everyone who joins.
  • You can change them at any time in the outpost. Mods that change how scenarios play can't be changed during an online scenario (the switch says so); change them back in the outpost.

The mods

Tradeable resources and equipment changes the game

Pass gold, lumber, metal, hide and items between characters in the party. Normally each character keeps their own.

How to use
  • In the outpost, hold Ctrl and click the portrait of one of your characters in the party column on the left, or click the GIVE button under their name at the top.
  • Resources tab: each column is another party member. Click a cell to give 1, right-click to take 1 back, Ctrl+click for 10, Shift+click for everything (or nothing).
  • Items tab: click the cell under the person who should get the item.
  • Nothing happens until you press Give. Esc closes the window without giving.
Good to know
  • Herbs aren't in it: the game already keeps herbs in one shared supply.
  • Nobody can own two copies of the same item, so someone who already has it can't be picked.
  • Gold and materials can also go to a character being created. Items go to party members only.

Share duplicate loot changes the game

When you loot an item you already own, the game normally sells it on the spot. With this on, the party decides who gets it, which is the board game's rule.

How to use
  • Nothing to do during the scenario. Back in the outpost, the usual item reward window opens: pick who gets it.
  • If nobody else in the party can take it, it's sold as usual. To sell it anyway, the new owner sells it in the shop for the same gold.

Easier item reward window convenience

The window that hands out item rewards (from events, quests and shared duplicate loot) is quicker to use.

  • It opens with nothing assigned, so you choose who gets each item instead of undoing the game's guess.
  • Left-clicking another character moves an item to them in one click.
  • Every item still has to go to someone before Done.

Reveal event outcomes shows hidden information

On town, road and boat events, hover over an option to see what it will do before you choose: the outcome story text, then its effects for your party (gold, damage, morale, items, an outpost attack, choices you'll be asked to make).

  • When an outcome depends on a random roll, it shows the roll you would actually get.

Show personal quest rewards no gameplay change

When a new character picks one of two personal quests, each card shows the building that quest unlocks when the character retires, like the board game's quest cards do.

  • It also shows what you'd get instead if someone unlocks that building first.
  • If another party member's quest would unlock the same building, it says so: whoever retires second gets the other building.
  • The extra quest you can draw with 15 inspiration when retiring shows it too.

Masteries carry over changes the game

Once a character earns a mastery, every later character of that class starts with that mastery already done, and gets its perk mark when created. No more re-doing the same awkward challenge for each new character of a class.

  • Only masteries earned while this rule is on count.
  • A carried mastery can't be earned a second time by the new character.
  • Masteries are still only earned in scenarios you win, as usual.

Dwarf's balance changes changes the game

A handful of changes from Dwarf74's Unofficial Frosthaven Campaign Tweaks. He maintains the official FAQ and was one of the main campaign playtesters. They smooth out spots many groups find frustrating:

  • Personal quests: once everyone has finished one, the quests that unlock the Tavern and the Stables come up first, and new quests prefer ones that still unlock something new.
  • Early Barracks: in the first winter, with good morale, the outpost event that upgrades the Barracks comes up early.
  • Shorter waits: personal quest 7's two waits are 5 weeks instead of 6. Personal quest 15 needs 60 gold.
  • Scenario 14 is reworked: you also have to defeat the Abael Herders, and the spawning monsters alternate rounds.
  • Boneshaper: the first mastery (kill 15 of your own summons) can be done across several scenarios.

More story events changes the game

More of your weekly town events move the story along: a new scenario, a section to read later, another event, a building, an item or a quest.

  • When the week's event is drawn and none of its choices could unlock anything new, it goes to the bottom of the deck and the next one is drawn instead.
  • Only once a week: the second card is kept, whatever it is, so quiet weeks still happen.
  • Outpost attacks are never skipped.
  • Roughly half of summer weeks and a quarter of winter weeks bring something new, instead of about a third and a seventh.

Game bug fixes changes the game

Fixes for mistakes in the game's own code. One switch for all of them:

  • Fair shuffles: the game's shuffle is slightly broken, which makes nulls and x2s a little more common than they should be. Attack modifier decks, the loot deck and similar draws are shuffled properly.
  • Co-op: fixes for several things that could put players out of sync or freeze the outpost.
  • Outpost: rebuilding doesn't cost extra morale, morale can't go below 0, the Jeweler's discount is charged as shown, the calendar shows the right week, and a few events work the way their cards say (which buildings get attacked first, cards that went missing from the town guard deck).
  • Quests and events: personal quest 14 needs five different areas, and the SO-10 delivery still arrives in later years.

Milestone saves no gameplay change

The game only keeps its last 15 autosaves, roughly the last hour or two of play. This makes a named backup at the start of every scenario and the moment the outpost opens after one (before the loot is handed out and the outpost events run), so you can go back further after a crash, a desync or a misclick.

  • They appear in the normal Load list as Mod backup - week 23 - scenario 14 start or Mod backup - week 23 - after scenario 14.
  • The newest 20 are kept. Your own saves and the game's autosaves are never touched.
  • Only the host's game makes them. To go back in co-op, the host loads the backup on their own, then hosts the game again and everyone rejoins.
  • Not available in Iron Man campaigns.

Battle stats no gameplay change

After each scenario, the Statistics tab gets about 40 extra rows: damage, kills, healing, shields, luck with your modifier deck, cards and elements used, exploration and more. Summons count for the character who summoned them.

  • The Campaign button at the top of the Statistics page shows each character's totals over every scenario played with this on. This scenario switches back.
  • Each finished scenario's full battle record is saved for the Stats tab of the companion app (charts of the whole party's campaign: luck, damage, rounds, trends). Wins, losses and resigns count; a restarted or unfinished scenario never does, and loading an older save takes back anything after it.

Modifier deck odds no gameplay change

In a scenario, right-click a character to open their info panel. Under Attack Modifiers (which shows how many of each card are left), it shows the odds of their next draw:

  • Null, -1/-2, +0, +1 or more, x2, and the chance of a rolling bonus. Curses count as nulls and blesses as x2s.
  • Each modifier icon also has a small tag with that card's own chance.
  • Right-click a monster to see the same for the monsters' deck.
  • It notes when a deck will reshuffle at the end of the round. It's the same math you could do from the counts the game already shows.

Scenario map file no gameplay change

Saves your campaign's progress (which scenarios are done, available or locked out) every time the game autosaves, for the scenario map page.

  • The map page shows every scenario, what unlocks it, what it leads to, and which ones lock each other out, coloured by your campaign's progress.
  • It also shows the choices that still matter (like which of two scenarios to play) and how many scenarios each option keeps open, so you can aim for the most scenarios in one campaign.
  • Spoilers: the map shows every scenario's name. Ask the host for the page if you want it.

If something goes wrong

  • "Out of sync" / desync message: before closing the game, everyone presses Ctrl+F7. It puts a zip file on your desktop. Send it to Kalarian along with what you were doing.
  • Something got lost or went badly: the host can load a Mod backup save (see Milestone saves).
  • Not sure everyone is on the same version: everyone runs the installer again. It shows the version it installed.
